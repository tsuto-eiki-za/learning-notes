# データフェッチ

## Chapter03 データフェッチ on Server Components

[データフェッチは ServerComponents](https://nextjs.org/docs/app/getting-started/fetching-data) で行うのがベストプラクティス

#### データフェッチを Server Components で行うメリット

- 高速にアクセスできる
- 非同期関数をサポートしているからシンプルに実装できる
- データフェッチはサーバー側でしか実行されないため、API をパブリックなネットワークに公開しなくていい
- バンドルサイズを軽減

## Chapter04 データフェッチ コロケーション

データフェッチはデータを参照するコンポーネントにコロケーションし、コンポーネントの独立性を高める！！

> **コロケーション**  
> コードをできるだけ関連性のある場所に配置すること。

あんまり上の方でデータフェッチをやってしまうと、バケツリレーが発生しがち。  
App Router では末端のコンポーネントへデータフェッチをコロケーションすることを推奨している。  
&Rightarrow; つまり、そのコンポーネントが使うデータはそのコンポーネントの近くで取ってきてね！！ということ

全く同じデータフェッチが色んなコンポーネントで実行されるのでは？  
&Rightarrow; [Request Memorization](https://nextjs.org/docs/app/guides/caching#request-memoization)でメモ化されているから大丈夫！！

## Chapter05 Request Memorization

データフェッチがメモ化されるのは URL・オプションが全く同じものだけ！！

オプションの指定ミスなどで Request Memorization が効かないことがないよう、データフェッチ処理はデータフェッチ層として分離する。  
&Rightarrow; LK の場合は fetchers ディレクトリを作ってる

データフェッチは基本的に Server Components で行いたい。  
&Rightarrow; server-only を利用してデータフェッチをクライアントサイドで行わないようにする。

```tsx
import "server-only";

export const getProduct = (id: string) => {
  const res = await fetch(`https://dummyjson.com/products/${id}`);

  return res.json();
};
```

## Chapter06 並行データフェッチ

取得したデータに依存関係がない場合は、並行してデータフェッチすると速度改善するよ！！

### データフェッチ単位のコンポーネント分割

とりあえずは、、、  
データフェッチ単位でコンポーネント分割を行うことがベスト

データ間に依存関係がなく参照単位もことなる場合には、データフェッチを行うコンポーネント自体を分割したい

### 並行 fetch()

取ってくるデータ同士の順番や依存関係はないけど、画面や処理で使う時にセットとして一緒に揃っていて欲しい場合は`Promise.all`を使って複数のデータフェッチを平行に実行できる。

```tsx
async function Page() {
  const [user, posts] = await Promise.all([
    fetch(`https://dummyjson.com/users/${id}`).then((res) => res.json()),
    fetch(`https://dummyjson.com/posts/users/${id}`).then((res) => res.json()),
  ]);

  // ...
}
```

### preload パターン

構造上親子関係にせざるを得ない場合、データフェッチにもウォーターフォールが発生する。  
このような場合は[preload パターン](https://nextjs.org/docs/app/getting-started/fetching-data#preloading-data)を利用することで、並行データフェッチを実現可能

ざっくりいうと、後で必要になるデータを前もって取りに行っておくパターン

普通に書くと、コンポーネントごとに `await` してしまって

1. 親コンポーネントがデータを取得
2. 子コンポーネントがその後データを取得
3. 孫コンポーネントがされにデータを取得

のように、順番待ち（ウォーターフォール）が発生してしまうことがある。
preload バターンは画面のレンダリングとデータの取得をできるだけ同時並行で進めたいという考え

#### ながれ

```tsx
// 1. 実際の取得関数
export async function getCurrentUser() {
  // fetchして結果を返す
  const res = await fetch("https://dummyjson.com/user/me");
  return res.json() as User;
}

// 2. 「先に投げておく」だけの関数
export const preloadCurrentUser = () => {
  void getCurrentUser(); // 結果はここではawaitしない
};
```

```tsx
// ページコンポーネント
export default async function Page() {
  // 1. ここで「ユーザー取っといて〜」とだけ依頼しておく
  preloadCurrentUser();

  // 2. そのまま子コンポーネントをレンダリング
  return (
    <>
      <Product />
      <Comments />
    </>
  );
}
```

1. 親コンポーネントで`preloadCurrentUser();`が`getCurrentUser()`を呼び出す
2. 実際のデータ取得がスタート
3. 後で`<Product />`や`<Comments />`が`await getCurrentUser()`を実行する。
4. Request Memorization により、`getCurrentUser()`の結果はメモ化されているので新しいリクエストは飛ばない！！

つまり、、、  
実際に`await`するのは`<Product>`側だけどリクエスト自体はもっと早いタイミングで実行が始まっている状態。

`<Product>`や`<Comments>`がユーザー情報を使わなくなったのに親に`preloadCurrentUser()`が残っている状態にならないように注意！

## Chapter07 N+1 と DataLoader

### N+1 問題

```tsx
import { type Post, getPosts, getUser } from "./fetcher";

export const dynamic = "force-dynamic";

export default async function Page() {
  const { posts } = await getPosts();

  return (
    <>
      <h1>Posts</h1>
      <ul>
        {posts.map((post) => (
          <li key={post.id}>
            <PostItem post={post} />
          </li>
        ))}
      </ul>
    </>
  );
}

async function PostItem({ post }: { post: Post }) {
  const user = await getUser(post.userId);

  return (
    <>
      <h3>{post.title}</h3>
      <dl>
        <dt>author</dt>
        <dd>{user?.username ?? "[unknown author]"}</dd>
      </dl>
      <p>{post.body}</p>
    </>
  );
}
```

```tsx
export async function getPosts() {
  const res = await fetch("https://dummyjson.com/posts");
  return (await res.json()) as {
    posts: Post[];
  };
}

type Post = {
  id: number;
  title: string;
  body: string;
  userId: number;
};

export async function getUser(id: number) {
  const res = await fetch(`https://dummyjson.com/users/${id}`);
  return (await res.json()) as User;
}

type User = {
  id: number;
  username: string;
};
```

上記のようなプログラムにおいて

1. まず`getPosts()`が一回だけ呼ばれて、投稿一覧を取得
2. 次に`posts`を`.map`で回して、`<PostItem />`を投稿の数だけ描画する
3. この時、投稿の数分`getUser()`が呼ばれる。

ここで、

- 投稿一覧取得：`getPosts()` 1 回
- 各投稿ごとにユーザー取得：`getUser()` 投稿の数だけ(N 回)

つまり、、、  
N + 1 回のリクエストが送られる。これを「N+1 問題」といふ。  
サーバーへの負荷が増え、遅くなったりするのでやめたほうがいい！！

### 対策

バックエンド側で、、  
ユーザーを 1 件ずつじゃなくて、**まとめて取れる API**を作る！

```txt
GET /users/?id=1&id=2&id=3
```

1 回のリクエストでユーザー１、２、３をまとめて取得するイメージ

**今回は上記のような API が実装済であることが前提です！！**  
このような API と Next.js の **DataLoader** を利用することで「N+1 問題」を解消します

### DataLoader

#### ざっくり

- いきなり API を叩かず、一旦「待ち合わせ場所」に集める係。
- 「あと数ミリ秒の間に、同じ種類のデータを取りたい人が何人か来るかも」と少しだけ待つ
- その短い間に集まったリクエストを見て、
  - id = [1, 2, 3] みたいに まとめて
  - バックエンドの「まとめ取得 API」に投げてくれる

> **バッチ処理**  
> たくさんの小さな処理をまとめて一気に実行すること

#### DataLoader の流れ

1. バッチ処理する関数を定義する  
   `myBatchFn(keys: readonly number[]) `みたいな関数
2. DataLoader のインスタンスを作る  
   `const loader = new DataLoader(myBatchFn)`

3. ページのあちこちで`loader.load(id)`が呼ばれる
4. DataLoader が、短い時間の中で呼ばれた id を集めて一度に関数を実行する

#### 先ほどの`getUser()`を DataLoader を使った形に書き換えてみる

**fetcher.tsx**

```tsx
import DataLoader from "dataloader";
import * as React from "react";

// ...

// DataLoaderのインスタンスを作る
// *React.cache*でラップすることでリクエストごとに1個だけDataLoaderを持つようにしている
const getUserLoader = React.cache(
  () => new DataLoader((keys: readonly number[]) => batchGetUser(keys))
);

export async function getUser(id: number) {
  const userLoader = getUserLoader();
  return userLoader.load(id);
}

// 引数にkeys([1, 2, 3])を取り、id=1&id=2&id=3のような形に変換してまとめてAPIを叩く関数
async function batchGetUser(keys: readonly number[]) {
  const res = await fetch(
    `https://dummyjson.com/users/?${keys.map((key) => `id=${key}`).join("&")}`
  );
  const { users } = (await res.json()) as { users: User[] };
  return users;
}
```

`Page.tsx`は書き換え不要.
裏側では、同時期に呼ばれた getUser() が 1 つのバッチにまとめられ、

- batchGetUser([1,2,3,...]) が呼ばれる
- N+1 が解消される

> **React cache**  
> [公式ドキュメント](https://ja.react.dev/reference/react/cache)

## ユーザー操作とデータフェッチ

基本的にデータフェッチは Server Components で行うことが基本。  
しかし、Server Components はユーザー操作に基づいてデータフェッチ・再レンダリングをするのに適していない
`router.refresh()` などでページ全体を再レンダリングすることはできるが、部分的に再レンダリングしたい場合に不適切

### 設計・プラクティス

Server Functions と`useActionState()`を使うことで、ユーザー操作に基づいたデータフェッチを実現できる。

### `useActionState()`

`useActionState()`
関数と初期値を渡すことで、Server Functions を通して更新できる State 管理ができる

実装例：

`app/search-products.ts`

```tsx
"use server";

export async function searchProducts(
  _prevState: Product[],
  formData: FormData
) {
  const query = formData.get("query") as string;
  const res = await fetch(`https://dummyjson.com/products/search?q=${query}`);
  const { products } = (await res.json()) as { products: Product[] };

  return products;
}
```

`app/form.tsx`

```tsx
"use client";

import { useActionState } from "react-dom";
import { searchProducts } from "./search-products";

export default function Form() {
  const [products, action] = useActionState(searchProducts, []);

  return (
    <>
      <form action={action}>
        <label htmlFor="query">
          Search Product:&nbsp;
          <input type="text" id="query" name="query" />
        </label>
        <button type="submit">Submit</button>
      </form>
      <ul>
        {products.map((product) => (
          <li key={product.id}>{product.title}</li>
        ))}
      </ul>
    </>
  );
}
```

Server Functions である`searchProducts()`を`useActionState()`の第一引数に渡すことで、form が submit されるごとに`searchProducts()`が実行される。

form 以外ほとんど要素がない単純なページであれば`router.replace()`で URL を更新・ページ全体を再レンダリングするという手段もある。  
この場合`useActionState()`のみでは実現が難しいリロード復元や URL シェアが実現できる。検索が主であるページにおいてはこっちを検討する
